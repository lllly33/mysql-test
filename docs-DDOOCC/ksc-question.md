
 概述
InnoDB 数据存储引擎是 B+Tree 数据结构进⾏存储的，⽽ B+Tree 在数据的写⼊和删除
阶段会触发 SMO 操作，在进⾏ SMO 操作时会对 B+Tree 添加全局 X-Latch，使得其他
事务⽆法对该 B+Tree 进⾏任何读写操作，使⽤云盘做存储介质后使得 SMO 的时间变成，
从⽽使得数据库的整体并发降低。
 问题描述
块存储延迟⾼：ESSD 读写延迟 200us 左右，本地盘 Nvme ⼤概在 10us
⾼并发写⼊性能弱：插⼊ / 删除可能触发节点分裂 / 合并，需锁定整个路径（如 InnoDB 的
意向锁 + ⾏锁），⾼并发写⼊时锁冲突严重，吞吐量受限。
动态调整成本⾼：
节点分裂 / 合并需复制⼤量数据（如⼀个节点分裂为两个，需复制⼀半数据），开销⽐较大，
并且需要跟磁盘做多次交互，使得锁的持有时间变的很⻓。
 优化⽅案

BLink-Tree（并发优化 B + 树，写⼊友好）
