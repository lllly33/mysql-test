# InnoDB B+Tree 性能测试 - 快速上手

> 适用版本：MySQL 8.0.34（源码路径：`/usr/local/mysql-8.0.34`）

## 测试目标

对比 InnoDB B+Tree 优化前后的性能差异，生成可视化报告。支持测试：

- **页分裂（Split）场景**：大量 INSERT 触发
- **页合并（Merge）场景**：大量 DELETE 触发
- **混合场景**：读写混合负载

## 前置准备

**1. 确认 MySQL 已启动**

```bash
# 本环境连接参数
host: 127.0.0.1
port: 3306
user: root
```

**2. 初始化测试表**（新实例需执行一次）

```bash
cd /usr/local/mysql-8.0.34
/usr/local/mysql/bin/mysql -h127.0.0.1 -P3306 -uroot -p密码 < tests/delay_injector.sql
```

**3. 创建产物目录**

```bash
cd /usr/local/mysql-8.0.34/tests
mkdir -p out/runs out/reports
```

**4. 配置数据库连接（推荐，避免在命令行暴露密码）**

```bash
# 复制配置文件模板
cp config.yaml.example config.yaml

# 编辑 config.yaml，修改数据库连接参数
vim config.yaml
```

## 快速开始（三步完成对比测试）

### 第一步：运行基准版本

**方法A：使用配置文件（推荐，隐藏敏感信息）**

```bash
cd /usr/local/mysql-8.0.34/tests
python3 test_framework.py --variant=baseline --config config.yaml
```

**方法B：命令行指定所有参数（不推荐）**

```bash
cd /usr/local/mysql-8.0.34/tests
python3 test_framework.py \
  --variant=baseline \
  --host=127.0.0.1 --port=3306 \
  --user=root --password=xxxx \
  --workload=insert \
  --threads=10 \
  --operations=10000 \
  --output_dir=out/runs
```

运行后会在 `out/runs/` 下生成一个包含时间戳的目录，里面有 `result.csv` 和 `result.json`。

### 第二步：运行优化版本

```bash
# 使用配置文件，采用相同参数
python3 test_framework.py --variant=optimized --config config.yaml
```

或者覆盖某些参数：

```bash
python3 test_framework.py --variant=optimized --config config.yaml \
  --workload=delete_heavy --threads=5
```

### 第三步：生成对比报告

```bash
python3 compare.py \
  --baseline "$(ls -dt out/runs/* | head -n 2 | tail -n 1)/result.csv" \
  --optimized "$(ls -dt out/runs/* | head -n 1)/result.csv" \
  --output out/reports
```

报告会保存在 `out/reports/` 下，文件名包含时间戳。用浏览器打开 HTML 文件即可查看图表。

## Workload 类型选择

| Workload              | 场景                                 | 何时使用                          |
| --------------------- | ------------------------------------ | --------------------------------- |
| `insert`            | 纯插入，大量页分裂                   | **测试 Split 优化**（推荐） |
| `delete_heavy`      | 先插入 1.5x，再删除 60%              | **测试 Merge 优化**（推荐） |
| `mixed`             | 50% INSERT + 30% SELECT + 20% UPDATE | 测试混合读写                      |
| `mixed_with_delete` | 含 10% DELETE 的混合负载             | 测试真实业务场景                  |
| `range_insert`      | 每个线程插入独立范围                 | 分散压力测试                      |
| `churn`             | 滑动窗口插入删除                     | 测试数据流失场景                  |

**示例：测试页合并优化**

```bash
python3 test_framework.py --variant=baseline --config config.yaml \
  --workload=delete_heavy --threads=5 --operations=2000
```

或编辑 `config.yaml` 修改默认值，然后：

```bash
python3 test_framework.py --variant=baseline --config config.yaml
```

## 关键指标说明

运行完成后，查看终端输出或 `result.csv`：

- **TPS**：每秒完成的操作数（越高越好）
- **P50/P95/P99 延迟**：50%/95%/99% 的请求延迟（越低越好）
- **index_page_splits**：页分裂次数（Split 场景关注）
- **index_page_merge_attempts/successful**：页合并尝试/成功次数（Merge 场景关注）
- **waits_top**：等待事件热点（在 result.json 中，帮助定位性能瓶颈）

对比报告会自动计算改进百分比并用颜色标识（绿色=改进，红色=退化）。

## 常见问题

**Q: 为什么优化版本反而更慢？**
A: 检查两次运行是否在相同环境（缓存状态、系统负载）。建议多次运行取平均值。

**Q: 如何验证真的触发了页分裂/合并？**
A: 查看输出的 `index_page_splits` 和 `index_page_merge_*` 指标，非零即触发。

**Q: 想调整并发数和数据量怎么办？**
A: 通过命令行参数覆盖：`--threads=50 --operations=5000`，或编辑 `config.yaml`。

**Q: 产物文件太多怎么办？**
A: 框架已自动分目录管理（runs/reports），可定期清理旧的测试结果：`rm -rf out`。

**Q: 如何避免在命令行暴露数据库密码？**
A: 使用配置文件 `config.yaml`。密码只需在配置文件中配置一次，所有命令都可以引用。参考"前置准备"步骤 4。

## 一键测试脚本（推荐）

如果你想测试别人给你的编译产物，可以使用：

```bash
/usr/local/mysql-8.0.34/tests/run_compare_binaries.sh \
  --baseline-bin /path/to/baseline/mysqld \
  --optimized-bin /path/to/optimized/mysqld \
  --workload insert \
  --threads 10 \
  --operations 10000
```

脚本会自动启动两个 MySQL 实例、运行测试、生成对比报告，并在结束时清理环境。
